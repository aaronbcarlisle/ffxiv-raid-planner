# Legacy V1 Schedule/Settings/Goals/Plugin + More Page Enumeration (Phase B)

**Method note (read before the tables):** `GroupViewContent.tsx` (`frontend/src/pages/GroupViewContent.tsx`) is the pageMode router. `pageMode==='schedule'` mounts `ScheduleUpcomingPanel` (Upcoming view) or `ScheduleTab` (Calendar view) - line 1087-1137, imports at lines 41-42. `pageMode==='goals'` mounts `GoalsPage` (`components/group/GoalsPage.tsx`) - line 1140-1152, import line 50. `pageMode==='more'` mounts `MorePage` (`components/group/MorePage.tsx`) - line 1155-1217, import line 49; this is the same component instance used by both the legacy shell and NewShell (v2) - there is no separate `pages/MorePage.tsx`; the task brief's path is approximate. `pageMode==='plugin'` mounts `PluginPage` (`components/group/PluginPage.tsx`) - line 1220-1225, import line 52.

`GoalsPage` does not mount `components/mount-farms/**`. It mounts `ObjectiveGoalsPanel` (Objectives sub-tab) and `CollectionsHub` (Farms sub-tab, in `components/collections/**`). `MountFarmTab`/`MountFarmSummary`/`MountFarmDetail`/`FarmProgress` (`components/mount-farms/**`) are exported from `components/mount-farms/index.ts:1` but have zero import sites anywhere in the app except their own internal chain and their own tests - they are orphaned/unmounted code as of this read. Only `FarmProgress`'s helper exports and `farmProgressUtils.ts` are consumed, by `components/profile/CollectionsTab.tsx` (a Profile-page surface, not `pageMode='goals'`). This is stated as fact, not a recommendation.

`ApiKeyManager.tsx` physically lives in `components/settings/` but is mounted only inside `PluginPage.tsx:97` - it is enumerated under P- (Plugin), not ST- (Settings), per its actual mount site.
