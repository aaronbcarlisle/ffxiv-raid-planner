## Rulings (bind every task)

### R-M-1 · the patch (O-1)
- `FindItem` gains `patch: string | null`, set to `c?.patch ?? null`.
- `FindRow`'s body line appends `Patch {n}` last: "{duty} · {type} · {expansion} · Patch 7.2". A null or empty patch adds nothing.
- The patch isn't searchable and isn't a filter.
- A viewer sees it: it isn't a count.

### R-M-2 · the singular (O-2)
`` ` · ${n} ${n === 1 ? 'needs' : 'need'} attention` ``, `n` still `issueMemberCount`. The e2e regexes become `needs? attention`.

### R-M-3 · the card model
`utils/objectiveCardModel.ts` exports:

```ts
export interface ObjectiveCardRow {
  id: string;
  title: string;
  description: string | null;
  /** "{category label} · {priority label}" */
  meta: string;
}
export function objectiveCardRows(objectives: StaticObjectiveGoal[], groupId: string): ObjectiveCardRow[];
```

- It keeps rows with `staticGroupId === groupId` and `priority !== 'not_doing'`, sorted stably by C-1. The `groupId` filter is what stops another static's list showing, since the store is unkeyed.
- Category label: from `OBJECTIVE_CATEGORY_OPTIONS`, falling back to the raw value. Priority label: Required, Preferred, Optional, falling back to the raw value with `_` as a space.
- An empty or whitespace-only description is `null`.

### R-M-4 · the card
`components/home/ObjectivesCard.tsx`, props `{ group: StaticGroup; canManage: boolean; onEdit?: () => void }`.
- A `CardShell as="div"` titled "Objectives" with a `Target` icon. `headerRight` is a `LinkText` "Edit" with `aria-label="Edit objectives"`, only when `canManage && onEdit`.
- The body is a `<ul>`. Each `<li>`: the title (`text-sm font-medium text-text-primary`), the meta (`text-xs text-text-secondary`), and the description when present (`text-xs text-text-secondary`). No tags: `Tag tone="info"` is under 4.5:1 in light (S2a-4a residual), and the priority reads as a word.
- Renders nothing when the effective role (`useStaticPermissions().userRole`) is null, when `objectivesError` is set, or when `objectiveCardRows` is empty. This matches `TrackCard`: a masked admin, or a View As of a non-member, sees neither card.
- It doesn't hide on `loading`, so a warm list doesn't blink on return to Home (the Farm card's S2a-4b residual).

### R-M-5 · Home
- An effect of its own, deps `[group.id, group.userRole, fetchObjectives]`, returning early with no `group.id` or no `group.userRole` (the fetch uses the actual role, as the Farm card's does). A guest sends no request.
- The card renders after `TrackCard` in the right column. `Home` gains `onEditObjectives?: () => void`, and NewShell's overview slot passes `() => useSettingsPanelStore.getState().open({ tab: 'recruitment', section: 'listing' })`. Don't build a URL: the seam already carries `?viewAs=` and the tier.

### R-M-6 · the editor on Listing (O-4)
`ListingTab` renders, between the status card and `DiscoveryTab`, `<div data-testid="listing-objectives"><CardShell as="div"><ObjectiveGoalsPanel key={group.id} groupId={group.id} canManage /></CardShell></div>`. `canManage` is literal: `RecruitPage`'s guard is the only way here, and the comment says so. `key={group.id}` restarts the panel on a static switch; Home now keeps the store warm, so its form state mustn't carry over. Listing can still show the old static's rows until the new fetch lands, and after a failed one (carried below; Delete is safe, the backend scopes it to the static). `ObjectiveGoalsPanel` is outside `DiscoveryTab`, so Save Listing and Cancel don't cover it; it saves on its own, as today.

### R-M-7 · the deep link (C-5)
In `NewShell`'s route component, a second arrival effect modelled on `:373-397`, with its own ref, once the group is loaded for the route:
- **Hold first.** When the URL has `viewAs`, decide nothing while `!authInitialized || (user?.isAdmin && viewAsUser?.userId !== viewAs && !viewAsError)`. Those values go in the deps, and the ref stays pending. Otherwise an admin viewing as a member is sent to Recruit and bounced to a remembered tab, and an admin viewing as a lead is sent to Home for good (plan-vet Critical). A failed View As read falls through to the real role.
- Only `goal === 'objectives'`. `goal=farms` and `farm=` keep landing on Progress (§4). It does nothing on the Recruit route.
- `canManage`: `navigate(withCarriedParams(recruitUrl(shareCode, 'listing', { tier: params.get('tier') }), location.search, ['goal', 'tab']), { replace: true })`.
- Otherwise, stay on the static: delete `goal`, set `tab=overview`, navigate with `replace`.
- A guest takes the second branch.
- Progress may mount for a frame first, as `rcsub`'s redirect allows. That's accepted.

### R-M-8 · the Settings tab (C-6)
- `SettingsPanel` gains two optional props, documented beside `hiddenTabs`: `tabLabels?: Partial<Record<SettingsTab, string>>` and `goalsSuggestionsOnly?: boolean`. `StaticSettingsHost` forwards both.
